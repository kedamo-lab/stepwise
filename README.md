# STEPWISE — обувной индекс

Учебный интернет-магазин обуви «Stepwise»: каталог моделей с размерными позициями и остатками,
корзина, оформление заказов и роли (клиент / менеджер / администратор). Лукбук на главной —
собственная 3D-сцена на three.js, карточка модели открывается во вращаемом вьюере
(Sketchfab embed).

Домен по заданию — «Чудо Обувь»; механика и арт-дирекшн вдохновлены becaneparis.com (плашки-чипы,
хайрлайны, нумерация всего, extended-типографика, нулевые радиусы), но контент, тексты и вёрстка
собственные.

## Стек

- **Frontend:** Vite + React 18 + TypeScript + React Router 6, обычный CSS (дизайн-токены в
  `src/styles/global.css`). 3D-сцена лукбука — three.js (GLTFLoader + ортокамера).
- **Backend:** Express 4, JSON-хранилище `server/data/db.json` (создаётся из `seed.js` при первом
  запуске). В dev Vite проксирует `/api` на порт 5174.

## Запуск

```bash
npm install
npm run dev          # API :5174 + Vite :5173 → http://localhost:5173
```

Production:

```bash
npm run build
npm start            # Express отдаёт dist/ и API на :5174
```

Сбросить демо-данные (остатки, заказы) можно из личного кабинета администратора кнопкой
«СБРОС ДАННЫХ» (POST `/api/reset`).

## Главная страница

1. **Лукбук** — вся коллекция в одной 3D-сцене (three.js, один WebGL-контекст): 10 пар стоят
   на общей линии пола с равными промежутками, каждая медленно поворачивается вокруг
   вертикали. Пара в покое приглушена (opacity 0.85), под курсором останавливается и
   становится полностью непрозрачной; подпись с ценой появляется при наведении, клик
   открывает модель. На телефоне тот же ряд прокручивается горизонтально.
2. **Переход к манифесту** — лукбук закреплён (`position: sticky`), поэтому при прокрутке
   первый экран остаётся на месте, а манифест наезжает на него сверху; сцена лукбука
   слегка отъезжает и гаснет.
3. **Манифест** — текст проявляется по словам по мере входа секции в экран; закрепления
   и наложения поверх лукбука внутри самой секции нет.
4. **Подвал** — на главной его нет: первый экран заканчивается манифестом. На остальных
   страницах подвал с чипами разделов и атрибуцией 3D остаётся.

Заголовок «ЛУКБУК» набран Dela Gothic One (файлы в `public/fonts/`, подключение в
`global.css`), остальная типографика — Bahnschrift.

Любой переход между разделами (клик по паре в 3D-сцене, карточка товара, корзина,
заказы, кнопка «назад») сопровождается появлением страницы сверху: контент опускается
на 40 px и проявляется за 0.6 с (`--route-in` в `global.css`, обёртка `.route-anim`
с ключом по маршруту в `App.tsx`).

Вкладки «Каталог», «Дропы» и «Журнал» открываются иначе — как окно поверх текущей
страницы: старая уезжает вниз на 5 % и притухает, а новая открывается сверху вниз за
0.58 с, пока не заполнит экран (`::view-transition-old(root)` с `@keyframes vt-old-push`,
`::view-transition-new(root)` с `@keyframes vt-panel-down` в `global.css`). Переход
построен на View Transitions API: клики по этим ссылкам перехватываются в `App.tsx`,
навигация выполняется внутри `document.startViewTransition`, а обычная анимация
появления для такого маршрута отключается классом `.route-anim--panel`. Если браузер
не поддерживает View Transitions, остаётся обычное появление сверху.

Каталог (`/index/products`) открывается из шапки («КАТАЛОГ») и по прямой ссылке,
где собрана вся сетка моделей с фильтрами, сортировкой и остатками по размерам.

Модели для сцены лежат в `sneakers-glb/`, рабочая копия — в `public/lookbook-models/`
(файл указан у товара в поле `glb`). Прозрачные PNG в `public/lookbook/` остались
от прежней версии сцены и в лукбуке больше не используются.

Рабочие GLB оптимизированы для браузера: геометрия упрощена, все части пары склеены
в один меш, вершины квантованы (`@gltf-transform optimize`). Итог — 3,3 МБ и 10 draw call
вместо 27 МБ и ~190 draw call, при этом исходники остаются в `sneakers-glb/`.
Сцена рендерится только когда она в кадре и не уехала под манифест, разрешение
ограничено и автоматически снижается при просадке кадров.

Превью товаров — прозрачные PNG в `public/models/` (по одному на модель). Они нарезаны
из общего файла `Файл со всеми кроссовками.png`: каждая пара вырезана по альфа-каналу,
приведена к единому холсту 640×400 и центрирована, поэтому в сетке каталога, в миниатюрах
дропов и в журнале все превью выглядят одинаково. Поле `image` у товара и обложки
материалов журнала указывают на эти файлы.


### Сущности (по ТЗ)

- **Пользователь:** логин, ФИО (+ роль для разграничения доступа).
- **Товар:** категория, подкатегория, производство, наименование, изображение, состав, описание,
  размерный ряд, доступные размеры, количество, цена, закупочная цена.
- **Товарная позиция:** модель + размер (+ остаток).
- **Заказ:** дата, ФИО клиента, товарные позиции, количество, цена за единицу, итоговая сумма.

Склад: при оформлении/редактировании/удалении заказа остатки товарных позиций уменьшаются или
возвращаются; сервер отклоняет заказ при нехватке (HTTP 409).

## Админ-панель

На странице `/orders` сотрудникам доступны вкладки, закреплённые по центру на уровне
шапки (`?tab=stats`, `?tab=editor`; без параметра открываются заказы). Менеджер видит
«Заказы» и «Статистику», администратор — ещё и «Редактор». Список заказов и его
таблица не меняются, вкладки только переключают содержимое ниже.

1. **Заказы** — прежняя таблица заказов с составом, редактированием и удалением.
2. **Статистика** — дашборд, который целиком считается на сервере (`GET /api/stats`) из
   заказов, склада и каталога: выручка, средний чек, прибыль и маржа, стоимость склада,
   динамика по месяцам или дням, структура расходов (закупка, логистика, эквайринг,
   упаковка), статусы заказов, топ моделей, бренды и размеры на складе, низкие остатки,
   последние заказы и сводка каталога. Каждый элемент появляется с задержкой: карточки
   въезжают, числа считаются через `requestAnimationFrame`, колонки и полосы растут,
   кольцо статусов рисуется через `stroke-dasharray`.
3. **Редактор** — CRUD каталога, дропов и журнала (`/api/admin/products|drops|stories`):
   список слева, форма справа. У модели редактируются название, бренд, категория, цена и
   закупка, размеры с остатками, дроп, изображение, состав, описание, 3D-файл и кредиты
   Sketchfab. У дропа — название, подзаголовок, лид и состав моделей; у материала журнала —
   заголовок, рубрика, обложка, лид, кредиты и связанные модели. Смена `slug` обновляет
   ссылки в дропах, журнале и заказах, удаление модели убирает её из дропов и журнала.

Закупочная цена пары (`cost` у товара) — база для прибыли и стоимости склада. Если поле не
заполнено, сервер берёт 46 % розничной цены. Тарифы логистики, упаковки и эквайринга заданы
в `server/stats.js` (`TARIFFS`) и показаны в интерфейсе, чтобы расчёт был прозрачным.
